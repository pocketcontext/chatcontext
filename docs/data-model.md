# ChatContext implementation contract

Default users identity for all clients. Source-only `team_members` holds `account` (unique users relation) and `is_admin` boolean. Google Workspace JIT grants ordinary team membership only on first admitted login; external OTP visitors get no membership. Administrators control roles/accounts; superusers bootstrap and maintain. `user_directory` has same id as users and only `name` (public display label). Directory SQL visible to team; visitors see self and authors of public messages in their own support conversations. Company label PocketContext.

Core collections (all ordinary mutations REST):
- conversations: kind `public_channel|private_channel|dm|support`, title, visitor (users relation for support), assignee (optional team account), status `open|resolved`, archived, created_by, updated_by, revision, created, updated. Creation accepts extra `participants` array for initial channel/DM membership. Creator automatically included. DM membership is immutable. Public channels readable to all team; subscription membership controls unread. Private channels and DMs require active membership. Support visible to all team and its one visitor. Any team member can reply/assign; visitor can create multiple conversations and change open/resolved. New visitor messages reopen resolved support.
- memberships: conversation, account, active, revision/stamps. Team-only; private channel members manage membership, public self-join/leave and team management, DM membership fixed. New channel members see full history; revocation immediate.
- messages: conversation, parent (optional root message for threads), body (Markdown text, max 20000), internal (support team-only), deleted (soft deletion), mentions (JSON account id array), author, revision/stamps. Only author edits/deletes, extra expected_revision required. Context/author/internal immutable. Delete clears ordinary body/mentions but retains audit originals. New thread replies inherit note visibility. No executing HTML.
- attachments: message, original (one protected immutable file max 25 MiB), sha256, author, revision/stamps. Owner uploads to own nondeleted message only. Deleting parent hides files. SQL reads metadata; protected file routes independently authorize.
- reactions: message, account, emoji, active, revision/stamps. Self-owned, unique message/account/emoji.
- read_receipts: message, account, revision/stamps. Explicit create acknowledges message; immutable. Unique account/message. SQL visibility self everywhere, other participants for DM/support only; never internal-note leakage. Query does not mutate.
- inbox: account, message, reason `mention|reply`, created; server managed. Visible only recipient while message remains accessible and nondeleted. Mentions notify named users; replies notify root author and previous participants. Visitors mention only visible team authors of their support conversation.
- changes: seq monotonic integer, collection, record, conversation, message, internal, action, created. No content; filtered by current conversation/message access. Stable SQL cursor, edits/deletions included. Membership changes require clients to discard inaccessible cached data; sync is distinct from read state.
- audit_log: collection, record, conversation, message, internal, actor, action, changes (JSON), created. Admin only AND conversation access. Support internal remains team only. No admin privacy bypass.
- source-only counters: key/value for transactional monotonic change numbering.

Seven-day app sessions with active client refresh; OTP 10-minute single-use with attempt limits and replacement invalidation. Anonymous direct signup blocked. Ordinary users can view only own auth record, not directory emails. No real data seeded. Initial admin operator-provisioned. No replies via email, only authentication mail. No external notifications or AI orchestration in server. Optional live updates are not required for v1; REST reads/realtime may be locked, primary consumer is SQL.

Retention indefinite; deletion soft; permanent erasure documented maintenance only, never implicit. Attachment complete backups target hourly snapshots and two-hour recovery; verify synthetic restore. Repository and container publication public as requested; no cloud deployment authorized. Candidate hostname chat.pocketcontext.com, independent Google client and chatcontext-backup bucket for future deployment. All configuration credentials private.
